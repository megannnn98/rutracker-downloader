# Авторизация: почему cookies, а не логин с паролем

Для CLI доступен [режим FlareSolverr](cli.md#flaresolverr): локальный браузер
получает clearance, затем запросы выполняет curl_cffi. В этом режиме достаточно
экспортированного `bb_session`; User-Agent берётся из ответа сервиса.
Описанные ниже ограничения обычного HTTP-клиента не означают, что этот режим
невозможен. Принятие сессии зависит от текущей защиты сайта.

Весь раздел `/forum/` на RuTracker закрыт Cloudflare Managed Challenge:

```
GET /forum/index.php     -> 200
GET /forum/login.php     -> 403, cf-mitigated: challenge
GET /forum/tracker.php   -> 403, cf-mitigated: challenge
GET /forum/dl.php        -> 403, cf-mitigated: challenge
```

В наблюдавшихся запусках `httpx` получал challenge даже со свежими cookies.
Обычный HTTP-клиент не исполняет JavaScript проверки; смена заголовков сама
по себе не гарантирует доступ.
Проверено отдельно: `index.php` отдаётся без challenge, но не выставляет ни
одной cookie, так что зайти «через главную» и получить сессию тоже нельзя.

Рабочий путь без браузерной автоматизации — взять cookies из браузера, где
проверка уже пройдена.

Логин по паролю (`--login`, `RUTRACKER_USERNAME` / `RUTRACKER_PASSWORD`) в коде
остался и заработает, если RuTracker когда-нибудь снимет challenge с
`login.php`. Сейчас он упирается в ту же проверку.

## Экспорт cookies

1. Откройте в браузере `https://rutracker.net/forum/tracker.php?nm=тест`
   и дождитесь, пока проверка Cloudflare пройдёт и покажется выдача.
2. Экспортируйте cookies домена `rutracker.net` в формате Netscape в файл
   `cookies.txt` в корне проекта (расширение вроде «cookies.txt», либо
   выгрузка из devtools). Нужны как минимум `cf_clearance` и `bb_session`.

Для Firefox это делает скрипт из репозитория:

```bash
uv run python scripts/export_firefox_cookies.py
```

Он работает с копией `cookies.sqlite` (оригинал залочен, пока браузер открыт),
пишет `cookies.txt` с правами `0600` и печатает только имена кук, без значений.
Флаги: `--db` — явный путь к базе, `--domain` — другой домен, `--out` — другой
файл.

## Срок жизни сессии

**`cf_clearance` привязан к паре IP + User-Agent и живёт около 30 минут.**
Отсюда два следствия:

* экспортируйте cookies непосредственно перед запуском;
* `RUTRACKER_USER_AGENT` должен совпадать с браузером **точно** — иначе
  Cloudflare вернёт challenge, даже если cookie свежая.

Если клиренс протухнет посреди прогона, утилита остановится с кодом `2` и
сообщением о том, что нужно переэкспортировать cookies. Уже скачанные файлы
при этом сохраняются, а повторный запуск не качает их заново — так что
перезапуск после обновления cookies стоит дёшево.

## Где хранится сессия

Рабочий cookie jar сохраняется в `~/.cache/rutracker-downloader/cookies.txt`
с правами `0600`. Исходный файл пользователя не перезаписывается. При запуске
берётся более свежий из двух по времени изменения: так обновлённый сервером
`bb_session` не теряется между запусками, а свежий экспорт из браузера всегда
побеждает старый кэш.

Профиль браузера (`cookies.sqlite`) утилита не читает — только тот файл,
который вы отдали явно.
