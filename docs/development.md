uv sync

uv run pytest -q
uv run ruff check .
uv run ruff format .
uv run mypy
node --test tests/test_browser_fetch.cjs

## Структура

```
src/rutracker_downloader/
├── cli.py         # argparse, коды возврата, печать статистики
├── config.py      # Settings из .env
├── client.py      # HTTP, повторы, задержки и cookies обычного режима
├── flare_client.py # опциональный FlareSolverr и curl_cffi транспорт
├── parser.py      # HTML → модели (чистый)
├── filters.py     # классификация audio/ebook/unknown (чистый)
├── naming.py      # безопасные имена файлов (чистый)
├── downloader.py  # оркестрация, идемпотентность, Stats
├── models.py      # TorrentEntry, SearchPage
└── errors.py      # типизированные ошибки
```

`parser.py`, `filters.py` и `naming.py` не знают про сеть и файлы — это и
делает их тестируемыми напрямую. `downloader.py` принимает `Protocol
SearchClient`, а не конкретный клиент, поэтому оркестрация проверяется
подставным клиентом без моков httpx.

## Тесты

Без внешней сети: парсер использует сохранённые фикстуры, большинство сетевых
тестов используют стабы. Тест CurlTransport поднимает временный HTTP-сервер
на loopback и проверяет реальный curl, cookies, сжатие и отключение proxy.
Для него нужны разрешённые локальные сокеты. Обращений к RuTracker в тестах нет.
Node.js-тест запускает браузерный сниппет с подставными DOM/fetch и таймерами:
он проверяет отложенный отзыв blob-URL, но не заменяет прогон в Firefox.

Покрыто в том числе: детект Cloudflare-challenge без ретраев, HTML вместо
торрента при протухшей сессии, `Retry-After` в формате HTTP-date, приоритет
cookie-jar'ов, гонка при сохранении файла, коды возврата CLI.

## Обновление фикстур

```bash
uv run python scripts/dump_fixtures.py
```

Нужны cookies (см. [authentication.md](authentication.md)). Скрипт снимает две
страницы выдачи, печатает, какие селекторы реально сработали, и вычищает из
фикстур `sid=`, `logout=`, `form_token`, ник и значения cookies.

Осторожно с санитайзером: он делает прямую подстановку, и короткие значения
вырезать нельзя. Одна из кук RuTracker имеет значение `1` — без ограничения на
длину она превращала `row1` в `rowREDACTED`, а `192 kbps` в `REDACTED92 kbps`.

## Проверка селекторов

Вёрстка форума меняется, поэтому у каждого поля в `parser.py` — цепочка
селекторов-кандидатов. Актуальное состояние, проверенное на живой выдаче:

| Поле | Селектор |
|---|---|
| строка | `table#tor-tbl tr[data-topic_id]` |
| название | `a.tLink` |
| категория | `td.f-name-col a` (`a.f-name` из старых парсеров **не существует**) |
| ссылка на торрент | `a.tr-dl` |
| пагинация | ссылки с `tracker.php` и `start=`, только со своего origin |

Пагинацию нельзя конструировать вручную: RuTracker подмешивает в ссылки
`search_id`, и собранный по шаблону URL вернёт другую выдачу.

## Мутационная проверка

После правок в парсере или фильтрах полезно сломать проверяемое место и
убедиться, что тест падает — иначе тест ничего не проверяет. Ловятся, в
частности: снятый origin-фильтр, `os.replace` вместо `os.link`, проверка
торрента по одному первому байту, `Retry-After` без HTTP-date, снятая
валидация аргументов, неперехваченный `OSError`.
